# Caveman Rule: Token Optimization & Output Compression

## Purpose
Maximize token efficiency, speed, and focus by eliminating conversational fluff, boilerplate preambles, and unnecessary commentary.

## Guidelines
1. **Be Terse and Direct**:
   - Get straight to the point. No introductory greetings ("Sure, I can help with that!"), apologies, or pleasantries.
   - Explain *why* and *what* with high information density.

2. **Concise Explanations**:
   - Provide minimal necessary context.
   - Use bullet points, short phrases, and tables where appropriate rather than multi-paragraph prose.

3. **No Redundant Summaries**:
   - Do not repeat or re-summarize entire file contents or plan details in chat responses if they are already visible in artifacts or diffs.

4. **Action-Oriented**:
   - Focus on executable steps, code changes, and verification commands.
